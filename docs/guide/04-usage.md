# 第4章: 実際の使い方

セットアップが完了したので、この章からは **実務で使うプロンプト集** を紹介します。辞書的にコピペして使ってください。

::: tip 📋 たとえ話: プロンプトは「外注先への発注書」
Claude Code へのプロンプトは、**外注先に渡す発注書**だと考えてください。

- 「いい感じに」だと毎回違うものが上がってくる
- 「要件・制約・納期」を明示すれば、一発で意図通りのものが返ってくる

この章のテンプレートは、その発注書のひな形です。
:::

## 基本: 読み取り

シートの内容を把握してもらう最もシンプルなパターン。

### プロンプト

```
以下のスプレッドシートの構造を把握して、どんなデータが入っているか教えてください。

URL: <シートの URL>
```

### Claude の動き

1. URL から `sheetId` を抽出
2. `listTabs` で全タブの一覧取得
3. 各タブについて `describeTab` でヘッダー・行数・列数を確認
4. 必要に応じて `readTab` で先頭数十行をサンプル読み
5. 要約を日本語で報告

### 補足

- 「A2 の値だけ教えて」のような単発なら `readCell` が 1 回叩かれるだけ
- 大量データは先頭 20〜50 行で構造把握してから方針を立ててくれる

## 使い捨て処理

結果だけ欲しい、コードは保存しなくてよい場合。

### プロンプト

```
以下のシートの「抽出」タブを集計して、
商品カテゴリ別の売上合計を教えてください。

URL: <URL>
```

### Claude の動き

1. 構造を把握
2. JavaScript（GAS）コードを生成
3. `runScript` で実行 → 結果を受け取る
4. 日本語で集計結果を提示

コードはどこにも保存されません。同じ処理をまた頼むと、Claude は毎回コードを書き直します。

## 保存型ロジック

「次回から同じ処理をボタン 1 つで」したい場合。対象シートの **コンテナバインド GAS** に保存されます。

### プロンプト

```
以下のシートに、「抽出」タブを集計して「集計結果」タブに
カテゴリ別売上を書き出す aggregateSales 関数を作って、保存してください。

URL: <URL>
```

### Claude の動き

1. 構造を把握
2. `aggregateSales` 関数を含むコードを生成
3. `writeBoundScript` で対象シートのコンテナバインド GAS に保存
4. 「『拡張機能 → Apps Script』で確認できます」と報告

スプレッドシートを開いて「拡張機能 → Apps Script」を覗くと関数が保存されています。次回以降は Apps Script エディタから **「実行」ボタンで起動** できます。

::: tip 保存型と使い捨ての使い分け
- 「次も使いそう」「自動化したい」「他の人にも使わせたい」→ 保存型
- 「今回だけ結果が欲しい」→ 使い捨て

迷ったら「保存して再利用できるようにして」と明示するのが無難です。
:::

## メニューボタン追加

スプレッドシートの上部に **独自メニュー** を追加して、関数をボタン化できます。

### プロンプト

```
以下のシートに「集計実行」というメニューを追加してください。
クリックしたら前回作った aggregateSales が走るようにします。

URL: <URL>
```

### Claude の動き

1. 既存の `aggregateSales` を保持するため `getBoundScript` で現在のコードを取得
2. `onOpen` トリガーで `SpreadsheetApp.getUi().createMenu('集計').addItem(...)` を追加
3. `writeBoundScript` でマージ後のコードを保存

スプレッドシートをリロードすると上部に新メニューが出ます。

## 時間トリガー（自動実行）

「毎朝 9 時に」「毎時」「毎週月曜に」といった定期実行。

### プロンプト

```
以下のシートの「抽出」タブを毎朝 9 時に自動更新したいです。
トリガーも仕掛けてください。

URL: <URL>
```

### Claude の動き

1. 更新処理のコード設計
2. Dispatcher の `installTimeTrigger` で `when: { type: "daily", hour: 9 }` を登録
3. トリガー登録完了を `listTriggers` で確認して報告

トリガーは **Dispatcher 側** に登録されます。Dispatcher があなたの Google アカウントで走ることで、毎朝 9 時にあなたの権限で処理が実行されます。

### 他のパターン

| when | 意味 |
|---|---|
| `{ type: "daily", hour: 9 }` | 毎日 9 時 |
| `{ type: "weekly", weekday: "MONDAY", hour: 9 }` | 毎週月曜 9 時 |
| `{ type: "hourly", hours: 1 }` | 1 時間ごと |
| `{ type: "every_minutes", minutes: 5 }` | 5 分ごと |

## 編集トリガー（反応型）

「A 列が編集されたら B 列に日時を入れる」のような反応型の自動化。

### プロンプト

```
以下のシートの「入力」タブで A 列が編集されたら、同じ行の B 列に
編集日時を自動で入れてください。

URL: <URL>
```

### Claude の動き

1. onEdit ハンドラのコードを設計
2. Dispatcher の `installSheetTrigger` で `eventType: "onEdit"` を登録
3. 編集が反映されることをユーザーに確認してもらう

## 既存 GAS の取り込み・機能追加

すでにコンテナバインド GAS が書かれているシートに機能追加するパターン。

### プロンプト

```
以下のシートには既存の GAS があります。
現在のコードを把握したうえで、月別ピボットを出す関数を追加してください。
既存機能は壊さないでください。

URL: <URL>
```

### Claude の動き

1. `getBoundScript` で現在のコードを全文取得
2. 既存関数を保持したまま新関数をマージしたコードを設計
3. `writeBoundScript` で書き戻し（全置換になるため既存コードの取りこぼしに注意）

::: warning 初見のシートで一発書き換えは禁物
Claude Code は、見覚えのない関数が残っていた場合「この関数は保持しますか？」と確認を入れる仕様です。勝手な全置換で既存ロジックが消えることはありません。

それでも初回は必ず自分でも「拡張機能 → Apps Script」を開いて、差分の妥当性を確認することを推奨します。
:::

## エラーが出たときの修正依頼

実行時エラーや想定外の挙動を直してもらうパターン。

### プロンプト

```
以下のシートの aggregateSales を実行したらエラーが出ました。
エラー文: "TypeError: Cannot read properties of null"

現在のコードを見て、原因を特定して直してください。

URL: <URL>
```

### Claude の動き

1. `getBoundScript` で現行コードを取得
2. エラー文と照合して原因を特定
3. 修正版を生成 → `writeBoundScript` で更新
4. 再実行して成功することを確認

エラー文をそのまま貼るのがコツです。スタックトレースごとでも可。

## 複数シート横断

シート A と B のデータを突合して C に書き出すなど。

### プロンプト

```
以下 2 つのシートを突合して、A にあって B にない商品 ID を
3 つ目のシートに書き出してください。

A: <URL-A>
B: <URL-B>
出力先: <URL-C>
```

### Claude の動き

- 各シートを個別に `readTab`
- 差分計算のコードを `runScript` で実行
- 結果を `writeRange` または `appendRows` で C に書き込み

## 外部 API 連携

BigQuery や他の Web API を組み合わせる場合。

### プロンプト

```
BigQuery の以下のテーブルを引いて、スプレッドシートに書き込む
GAS を作って保存してください。

プロジェクト: tiast-data-platform
テーブル: dataset.table_name
URL: <シートの URL>
```

### Claude の動き

- BigQuery Service を使った GAS を生成
- `writeBoundScript` で保存
- 初回実行時に OAuth 承認が必要な旨を案内

API キーが必要な外部サービスの場合、Claude は **スクリプトプロパティ（`PropertiesService`）** 経由で管理する構成を提案します。コードに直書きしません。

## プロンプトのコツ

### ✅ 効くコツ

- **URL を完全な形で渡す**（`docs.google.com/spreadsheets/d/.../edit` まで）
- **目的 → 入力 → 期待する出力** の順で書く
- 大量データなら「先頭 50 行を見て構造把握してから方針決めて」と明示
- 「保存して」「使い捨てでいい」を明記すると意図のブレが減る

### ❌ 効きにくい

- 「いい感じに」「前と同じ感じで」（前を憶えていない）
- 単独の日本語指示のみ、URL なし
- シートの中身を言葉で説明しすぎる（「Claude に読ませる」が早い）

### 破壊的操作の扱い

以下の操作は Claude Code が **事前にあなたへ確認** します。

- タブ全消去（`clearTab`）
- コンテナバインド GAS の全置換（差分マージできない場合）
- 複数トリガー一括削除
- 大量行削除、`clear()` などを含む `runScript`

「OK で」と明示的に返さない限り実行されません。
