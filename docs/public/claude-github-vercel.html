Claude × GitHub × Vercel ことはじめ

3つの道具がどう協力して「サイトが公開される」までを作るか、図でわかる入門ガイド

1. まず、登場人物は3人だけ

難しく考えなくて大丈夫です。家を建てるのに「大工さん・倉庫・お店の人」がいるのと同じで、ウェブサイトを作って公開するにも 3 つの役割があります。

🤖

Claude

大工さん

あなたの指示でコードを書いてくれる AI。設計図どおりに「家（コード）」を組み立てる職人さん。

📦

GitHub

倉庫＆履歴ノート

書いたコードを保管する場所。「いつ・誰が・何を変えたか」もすべて記録してくれる。

🌐

Vercel

お店の人

倉庫からコードを受け取って、世界中からアクセスできる「お店（ウェブサイト）」として公開してくれる。

ポイント：あなたは「依頼する人」。3 人がバトンをつないで、サイトを世に出してくれます。

3. なぜ 3 つ必要？ 役割分担の理由

もし無かったら…こうなる
Claude が無いコードを全部自分で書くことになる。時間も知識も必要。
GitHub が無いコードが自分のパソコンの中だけ。壊れたら終わり。誰とも共有できない。
Vercel が無いコードはあるけど、サーバーを自分で借りて設定しないと公開できない。

つまり 3 つ揃うと、「思いつく → 形になる → 公開される」が一直線になります。

5. 用語集（日常の言葉で）

リポジトリ (repository / repo)
📦 GitHub 上の「プロジェクト1個ぶんの箱」。サイトひとつにつき箱ひとつ、と思えば OK。
commit（コミット）
📝「ここまでの変更を1つの区切りとして記録する」こと。日記に「今日やったこと」を書くイメージ。
push（プッシュ）
📤 手元の変更を GitHub の倉庫に「送る」こと。コミットしただけではまだ手元。push して初めて世界に届きます。
pull（プル）
📥 push の逆。GitHub にある最新を手元に「取ってくる」こと。
branch（ブランチ）
🌿 「お試し作業用の枝分かれ」。本番のコードを壊さずに新機能を試せる安全な作業場所。
merge（マージ）
🔀 枝分かれしていたブランチを「本流に合流」させること。OK が出た作業をみんなの本番コードに取り込む瞬間。
Pull Request (PR)
🙋「このブランチをマージしてもいいですか？」というお伺い。レビューや議論の場にもなる。
deploy（デプロイ）
🚀 コードをサーバーに置いて「実際に動く状態にする」こと。Vercel がこれを自動でやってくれます。
preview（プレビュー）
👀 本番に出す前に「こう見えますよ」と試せるお試し URL。Vercel はブランチごとにこれを自動で作ってくれます。

🟢 main = 本番の安全な本線。🟡 feature = お試し用の脇道。脇道で作業してOKなら本線に合流（merge）。失敗しても本線は無傷です。

7. つなぎ方（セットアップの全体像）

1

GitHub にアカウントを作って、リポジトリ（箱）を1つ作る

無料で OK。これが「コードの倉庫」になります。

2

Vercel にアカウントを作って、GitHub と連携する

「GitHub でログイン」を選び、さっき作ったリポジトリを Vercel に紐づけます。これで GitHub に push されると Vercel が自動で気づくようになります。

3

Claude にリポジトリを触ってもらう

Claude Code（または Claude のウェブ版）にリポジトリを渡し、「こういうサイトを作って」と依頼。Claude がコードを書いて GitHub に push してくれます。

4

あとは自動！

push されると Vercel が検知 → ビルド → 公開 URL に反映。あなたはブラウザで結果を確認するだけ。

9. よくある質問

Q. お金はかかる？

個人の練習レベルなら GitHub も Vercel も無料枠で十分です。Claude は有料プランが必要になることがあります。

Q. 間違えて変なコードを push したら？

GitHub は履歴を全部覚えているので、いつでも「前の状態に戻す」ことができます。これが GitHub を使う一番のメリットです。

Q. Vercel じゃないとダメ？

同じ役割をする会社は他にもあります（Netlify, Cloudflare Pages など）。Vercel は GitHub との連携がいちばん簡単なので入門におすすめ。

Q. PR の「auto-merge（自動マージ）」がグレーアウトして使えない

GitHub の仕様で、無料プラン × 非公開（private）リポジトリの組み合わせでは auto-merge が使えません。次のいずれかで解決します:

  • リポジトリを Public にする（ただし秘密の鍵やトークンを公開しないよう要注意）
  • GitHub Pro（月 $4 程度）以上にアップグレード
  • そのまま 手動でマージ する（実用上は問題なし。Claude にマージを依頼してもOK）
個人練習なら「手動マージ」で十分です。チーム開発で CI 通過後に自動で取り込みたくなったら Pro を検討。
